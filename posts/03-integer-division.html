1 除以 2 居然等于 0

2026-10-22 · C 语言 · 数据类型

接上一篇。我把编译问题解决了，程序终于肯跑新代码了。然后输出变成了 0。

不管我输入什么时间，结果永远是 0。物理量算出来是 0，这在现实里说不通。

我一开始怀疑公式

自由落体的位移公式是 s = ½ · g · t²。我写的是：

s = 1/2 * g * t * t;

我翻了书，公式没错。g 我定义成 9.8，t 是输入的 6，哪个都不该是 0。

然后我做了一件现在看来很对的事：不猜了，直接打印出来看。我单独加了一行：

printf("%d\n", 1/2);

输出：

0

原因：整数除法会直接把小数扔掉

C 语言里，两个数做除法，结果是什么类型，取决于这两个数本身是什么类型，而不是取决于"数学上应该等于多少"。

  • 1 是整数，2 是整数。
  • 整数 ÷ 整数 = 整数。
  • 1/2 数学上是 0.5，但作为整数，它只能是 0。
  • 小数部分直接砍掉，不是四舍五入。

所以整条式子就变成了：

s = 0 * 9.8 * 6 * 6;   /* 0 乘以任何数都是 0 */

整个公式被最前面那个 0 给吃掉了。

我踩的坑

把数学公式直接照抄进代码。1/2 在纸上和在计算机里不是一回事——计算机先问"这俩数是什么类型"，再决定怎么算。

怎么改

只要让参与运算的数里有一个是小数，结果就会变成小数。随便挑一种：

s = 1.0/2 * g * t * t;    /* 把 1 写成 1.0 */
s = 0.5 * g * t * t;      /* 直接写 0.5，最省事 */
s = 1.0/2.0 * g * t * t;  /* 两个都写成小数，最保险 */

顺带记住的几个

  • 5/2 → 2（不是 2.5）
  • 5.0/2 → 2.5
  • 7/2 → 3（不是 3.5，也不是 4，是往下砍不是四舍五入）
  • -7/2 → -3（往 0 的方向砍）
记住这一条

看到除法先停半秒：斜杠两边的数，是整数还是小数？只要两边都是整数，小数就一定没了。想留小数，就把其中随便一个写成带点的形式。
