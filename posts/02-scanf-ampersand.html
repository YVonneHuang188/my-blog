scanf 里那个 &，到底是什么东西？

2026-10-21 · C 语言 · 指针入门

学输入的时候，教材上写的是这样的：

int r;
scanf("%d", &r);

我照抄没问题。但有一次我手快，写成了：

scanf("%d", r);   /* 少了 & */

编译居然通过了，还给了个警告我没看懂。程序一运行，直接崩溃。终端里冒出来一行 SIGTRAP，我完全不知道那是什么。

& 是"取地址"

这个符号念作"and"，但在变量前面它不是"和"的意思，它的意思是取地址——拿到这个变量在内存里住在哪儿。

为什么非要地址？打个比方：

你要让快递员把一个包裹放进你家的柜子。你跟他说"柜子是空的"，他听懂了，但他不知道你家在哪儿，包裹就送不到。你必须告诉他地址。

scanf 就是这个快递员。它的工作是"把你从键盘敲进去的数，放回到某个变量里"。所以它需要两样东西：

  • 第一个参数 "%d"：告诉它包裹是什么类型的（一个整数）。
  • 第二个参数：变量在哪儿。也就是地址。

如果你直接写 r，给它的是柜子里现在装的东西（而且 r 还没初始化，里面是个随机垃圾值）。scanf 拿着这个垃圾值当地址去找，找到了一个根本不属于它的内存位置，往里写东西——操作系统一看，"你在乱动别人的地盘"，直接把程序掐掉。这就是崩溃。

我踩的坑

少写一个 &，程序运行时崩溃（SIGTRAP）。这类错误编译器不一定拦得住，它可能只是警告一下就让你过了，然后崩给你看。

顺便：printf 为什么不用加 &

我当时还糊涂过这个：scanf 要 &r，printf 却直接写 r？

因为它们的活儿不一样：

  • scanf 是写入——它要往变量里放东西，所以它得知道变量在哪儿 → 要地址。
  • printf 是读取——它只要把变量现在的值打印出来，给我值就够了 → 不用地址。

还有一个配套的小坑

double 类型（带小数的数）在这儿还有个额外讲究：

double r;
scanf("%lf", &r);    /* 读入用 %lf，lf = long float */
printf("%f", r);     /* 打印用 %f 就够了 */

同一个变量，读和打印用的格式符居然不一样，我一开始觉得这设计真别扭。原因跟 C 语言函数传参的规则有关（float 传进去会自动变 double），先记住这个结论就行。

记住这一条

凡是要"把结果写回某个变量"的函数，都要给地址，也就是变量名前面加 &。scanf 是最常遇到的一个。
